# หน้าจอและเส้นทางผู้ใช้

## 1. เริ่มจากแผน

เปิด surface แล้วเห็นหน้าเดียวที่มีโหมดปัจจุบัน สถานะตลาด TH สถานะสัญญาณ Global และรายการอันดับ ปุ่ม “ลองแผนจำลอง” ใช้การตั้งค่าเงินจำลองเริ่มต้น ผู้ใช้ดูการ์ดและกดรับหรือข้ามได้ทันที

| ส่วน | สิ่งที่ต้องแสดง |
| --- | --- |
| อันดับ Global | เหรียญ คู่ TH ที่จับคู่ได้ ผลตอบแทน 30 วันใน USDT ส่วนต่างจาก BTC วัน UTC ที่ใช้ จำนวนคู่ที่วัดได้ และเหตุผลที่บางคู่เข้าคิวหรือถูกข้าม |
| การ์ดแผน | คู่ ฝั่งซื้อหรือขาย จำนวนและราคา limit ค่าใช้จ่ายประมาณการ จุดที่ทำให้แผนใช้ไม่ได้ และสิ่งที่เกิดถ้าจับคู่ได้บางส่วน |
| ทางเลือกด้วยตัวเอง | เลือกคู่ที่รองรับ กำหนดราคาและจุดออก แล้วให้ระบบคำนวณขนาดจากเพดานที่ตั้งไว้ แสดงเหตุผลเมื่อขนาดที่ส่งได้ต่ำกว่าขั้นต่ำ |
| คำสั่งและสถานะ | เงินจำลองหรือเงินจริง ยอดที่ส่งและจับคู่แล้ว ยอดสุทธิที่ถือและขายได้ เกิดอะไรขึ้นกับที่เหลือ คำสั่งป้องกันครอบคลุมเท่าไร และข้อมูลล่าสุดเมื่อไร |
| ประวัติ | เทียบแผนก่อนส่งกับผลที่เกิดขึ้น ราคาเฉลี่ย fee กำไรขาดทุน และเหตุผลที่ข้ามหรือถูกบล็อก แยกประวัติ paper กับเงินจริง |

หน้าจอใช้ตำแหน่งปุ่มและคำเรียกคงที่ AI อธิบายการ์ดและผลได้จากข้อมูลที่ระบบวัดไว้ ตัวเลข เงื่อนไขและปุ่มส่งทำงานได้เมื่อ AI ไม่พร้อม

## 2. จาก paper ไปซื้อและขายจริง

1. กด “ใช้เงินจริง” เพื่อเชื่อมบัญชี Binance TH ตาม [ขั้นตอนเชื่อมบัญชี](venue.md#3-เชื่อมบัญชีสำหรับเงินจริง) และตั้งเพดานเป็นเงินบาท หน้าเชื่อมแสดงผลตรวจ key และการอ่านยอด
2. กลับมาที่แผนหรือเลือกคู่เอง เห็น ticket ที่ระบุ “เงินจริง · Binance TH” พร้อมราคา จำนวน ต้นทุน และสถานะจุดออก การ์ดจาก paper ใช้ข้อมูลฝึกต่อได้ แต่การส่งจริงต้องสร้าง ticket ใหม่จากยอดและสมุดคำสั่งปัจจุบัน
3. กดยืนยันซื้อ เห็นสถานะ “กำลังส่ง”, “จับคู่บางส่วน”, “จับคู่ครบ”, “ไม่จับคู่/หมดอายุ” หรือ “กำลังตรวจผล” พร้อม order ID เมื่อมี ในสถานะกำลังตรวจ ให้มีทางตรวจรายการเดิมและเหตุผลว่าทำไมกดส่งใหม่ไม่ได้
4. เปิดสถานะที่ระบบดูแล เห็นจุดออกแบบ manual เป็นค่าเริ่มต้น ถ้าคู่ผ่านการทดสอบ native stop ให้เสนอ “ตั้งคำสั่งป้องกันที่ Binance TH” หลังรู้จำนวนที่ซื้อได้จริง แยกข้อความ “exchange รับคำสั่งแล้ว” ออกจาก “ขายแล้ว”
5. กด “ขายลดสถานะ” แล้วดู ticket และยืนยันใหม่ หน้าผลเขียนจำนวนคงเหลือและ P&L สุทธิเมื่อวัดได้ หากมี stop จองเหรียญอยู่ ให้นำทางยกเลิกและตรวจผลก่อนออก ticket ขายใหม่
6. ขณะใช้เงินจริง ปุ่ม “หยุดเปิดไม้ใหม่” เข้าถึงได้ในคลิกเดียว เห็นสถานะหยุด คำสั่งที่ยังรอยืนยัน และลิงก์ไปจัดการใน Binance TH กรณีเน็ตหลุดหรือแอปปิด

จำนวนไม้จำลองไม่เป็นเงื่อนไขในการใช้เงินจริง สิ่งที่ต้องผ่านคือการตรวจบัญชี ข้อมูลที่ใช้ส่ง และการยืนยัน ticket ตาม [กติกาคำสั่ง](trading.md#2-สร้างและยืนยันคำสั่งจริง)

## 3. อธิบายตอนที่เกี่ยวกับการตัดสินใจ

| เหตุการณ์ | ข้อความที่ผู้ใช้ควรเข้าใจ |
| --- | --- |
| Global ส่งแท่งวันใหม่ไม่ครบ | อันดับหยุดที่วันไหน และยังเลือกคู่เองได้เมื่อข้อมูล TH พร้อม |
| กำไรขั้นต้นถูก fee กิน | ซื้อและขายเสียเท่าไหร่ และทำไมกำไรสุทธิต่างจากที่เห็น |
| ขนาดต่ำกว่าขั้นต่ำ | คำสั่งไหนต่ำกว่าเกณฑ์กี่บาท และทำไมเพิ่มขนาดให้เองไม่ได้ |
| ซื้อได้บางส่วน | เหลือเหรียญสุทธิเท่าไหร่ ยอดที่ไม่จับคู่เกิดอะไรขึ้น และขายได้เท่าไร |
| ราคาข้ามจุดออกหรือ stop-limit ไม่ fill | อะไรคือจุด trigger อะไรคือคำสั่งที่อยู่บน exchange และตอนนี้ถืออยู่เท่าไหร่ |
| ผลยังไม่ทราบหลังขาดการเชื่อมต่อ | ระบบจะเช็กคำสั่งเดิมให้ และผู้ใช้เปิดไปดูที่ไหนได้ |

ใช้การ์ดสั้นที่ผูกกับเหตุการณ์และปัดได้ ข้อมูลสถานะเงินจริงและเหตุผลที่บล็อกยังอยู่บนหน้าหลักเมื่อปัดบทเรียน แผนการเรียนขั้นต่อไปคือเปรียบเทียบกลยุทธ์และปรับพารามิเตอร์ทีละค่าเมื่อมีผลให้เทียบ

## 4. วัดว่าหน้าจอใช้ตัดสินใจได้

- คนเปิดครั้งแรกเห็นแผนจำลองหรือเหตุผลที่ยังไม่มีแผนได้ภายในสองนาที โดยไม่ใช้ credential
- ก่อนยืนยัน ผู้ทดสอบอธิบายได้ว่าเป็นเงินประเภทไหน จ่ายสูงสุดเท่าไร ราคาเปลี่ยนเกินเงื่อนไขแล้วจะเกิดอะไร และคำสั่งป้องกันอยู่ที่ไหน
- เมื่อจำลอง partial fill/timeout/offline ผู้ทดสอบบอกได้ว่ามีอะไรค้างอยู่และไปตรวจที่ Binance TH ได้ โดยไม่สร้างคำสั่งซ้ำ
- ผลงานเทรดรายงานกำไรขาดทุนสุทธิ จำนวนแผนและจำนวนที่ fill ช่วงข้อมูล และ drawdown เมื่อมีข้อมูลพอ แสดงตัวชี้วัด live แยกจาก paper และ backtest
- เมื่อแต่ละเส้นทางผ่าน [เกณฑ์ระบบและ live pilot](trading.md#6-การทดสอบและเกณฑ์เปิดใช้) ให้เก็บหลักฐานแยกตามคู่และชนิดคำสั่ง เกณฑ์หลักของรุ่นแรกคือซื้อและขายสินทรัพย์ในคู่ THB ครบหนึ่งรอบและตรวจย้อนหลังถึง fill ที่ exchange ได้
